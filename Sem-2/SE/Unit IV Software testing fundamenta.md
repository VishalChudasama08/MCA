**Unit IV: Software testing fundamentals**



**Software testing** is the process of checking to find error and verify is works according to requirements. 



**Verification** is the process of checking whether software is being developed correctly according to requirements. 

"Are we building the software correctly?"



**Validation** is the process of checking whether the final software meets to user requirements.

"Are we building the correct software?" 



**Qualification** is the process of confirming that software is ready and suitable for use.



**STLC** (Software testing life cycle): systematically and efficiently follow step-by-step testing process for software testing is called STLC

&#x20;   1. Requirement Analysis    - Tester studies requirements carefully.

&#x20;   2. test planning           - tester create a testing plan. what, how test

&#x20;   3. test case development   - tester write test cases.

&#x20;   4. test environment setup  - preparing environment for testing.

&#x20;   5. test execution          - now actual testing starts.

&#x20;   6. test closure            - tester make final report, bug summary, result



**Levels of Testing**

&#x20;   1. Unit Testing        (First check small module)   - is testing individual small components/modules of software.

&#x20;   2. Integration Testing (then connected modules)     - checks whether combined modules work properly together.

&#x20;   3. System Testing      (then check full software)   - tests the complete integrated software system.

&#x20;   4. Acceptance Testing  (then customer checks)       - checks whether software is ready for deliver and satisfies customer requirements.



**Types of Testing**

&#x20;   1. Manual Testing          - testing software manually without using automation tools.

&#x20;   2. Automation Testing      - use tools/scripts to test software automatically. (Selenium, TestNG, JUnit)

&#x20;   3. Functional Testing      - checks whether software functions work according to requirements. "Is software doing correct work?"

&#x20;   4. Non-Functional Testing  - checks Performance, Security, Usability, Reliability (all quality factors.) "How well software work?" 



**Testing Techniques** 

&#x20;   1. Black-box Testing  (outer check)  - tests software functionality without knowing internal code.

&#x20;   2. While-box Testing  (inner check)  - tests internal code structure and programming logic.

&#x20;   3. Grey-box Testing   (combine both) - testing with partial knowledge of internal code.



**Test Case Design Techniques** - When tester test software, they create test cases. But testing every possible input is very difficult. So tester use smart techniques. 

&#x20;   1. Boundary Value Analysis (BVA) - testing technique where testing is done on minimum and maximum limit values.

&#x20;   2. Equivalence Partitioning (EP) - divides input data into valid and invalid groups for testing 



Writing Effective **Test Plans** **and Test Cases**

&#x20;   1. Test Plans - Document describing testing strategy, objectives, schedule and resources.

&#x20;   2. Test Cases - set of steps used to check a feature.
